# 报关智能体平台侧同服务器集成与联调交接说明

更新时间：2026-06-20
协议版本：Agent V1 / Schema 1.0
适用阶段：单服务器演示部署、平台侧首次联调、后续正式集成前的技术交接

## 1. 文档目的

本文档用于向平台侧开发人员说明：

1. 报关智能体服务目前已经实现哪些能力。
2. 平台侧和智能体侧分别负责什么。
3. 两套系统部署到同一台服务器后如何连接。
4. 平台如何创建任务、消费流式事件、查询最终结果和下载文件。
5. 当前演示版本的边界、限制和后续扩展方式。

本次集成目标不是把智能体前端嵌入平台，而是把报关智能体作为一个独立后端能力服务，由平台后端统一调用和展示。

## 2. 当前结论

目前已经具备一条可用于平台演示联调的完整调用链：

```text
平台后端
  -> 创建智能体任务
  -> 获得 run_id
  -> 消费 SSE 流式事件
  -> 展示文本增量和工具调用状态
  -> 查询最终状态和结构化结果
  -> 展示或下载智能体生成文件
```

平台只需要对接一组统一的 Agent V1 接口，不需要直接调用智能体内部的审单、法规、报告或工具接口。

统一前缀：

```text
/api/agent/v1
```

核心创建入口：

```http
POST /api/agent/v1/runs
```

当前真实 HTTP 烟测结果：

- 服务健康状态：`ok`
- 协议版本：`1.0`
- Run 存储：`SQLiteRunStore`
- 文件中心：`local_fallback`
- 能力描述数量：8
- Agent V1 自动化回归：47 项通过

## 3. 推荐的同服务器部署结构

推荐将平台和智能体部署在同一台服务器上，但保持为两个独立进程：

```text
用户浏览器
    |
    v
平台前端 / 平台网关
    |
    v
平台后端，例如 127.0.0.1:8080
    |
    | HTTP + SSE，仅服务器内部访问
    v
报关智能体服务 127.0.0.1:8000
    |
    +-- LLM
    +-- 本地知识库
    +-- 审单引擎
    +-- Skill / MCP 工具
    +-- SQLite Run 存储
    +-- 临时 Output 文件目录
```

推荐原则：

- 浏览器只访问平台，不直接访问智能体服务。
- 平台后端通过 `http://127.0.0.1:8000` 调用智能体。
- 平台负责用户登录、权限和页面展示。
- 智能体服务只监听服务器内网或回环地址。
- 平台可以将智能体接口反向代理为自己的内部接口，避免跨域和凭证暴露。

不建议首期把两套代码强行合并到同一个进程。独立进程更方便启动、停止、排错、升级和回滚，同时仍然属于同服务器部署。

## 4. 双方职责划分

### 4.1 我们负责的内容

报关智能体侧负责：

- 统一 Agent V1 调用协议。
- 通用智能体及全部已注册工具的调用能力。
- 系统级提示词和工具调用边界控制。
- 固定审单工作流。
- 法规知识库检索。
- 报关数据查询适配。
- 报告生成。
- 演示版完整审查链路。
- SSE 流式事件生成。
- Run 状态、事件顺序和幂等控制。
- SQLite 单机任务持久化。
- 生成文件的临时托管和下载。
- 可选的平台文件中心上传适配。
- 可选的服务密钥认证和租户隔离。
- 统一错误结构、追踪 ID 和任务取消。

### 4.2 平台侧负责的内容

平台侧负责：

- 用户登录、用户身份和权限校验。
- 生成并维护 `user_id`、`tenant_id`、`session_id`。
- 为每次请求生成唯一 `request_id`。
- 调用 `POST /runs` 创建任务。
- 消费 SSE 事件并更新前端界面。
- 展示智能体文本、工具执行状态、警告和最终结果。
- 根据 `outputs` 展示文件名称、类型、大小和下载按钮。
- 通过平台后端代理智能体文件下载。
- 对失败请求按照 `retryable` 决定是否重试。
- 正式上线后提供平台文件中心上传接口。
- 正式上线后提供真实报关业务系统接口或 mock 接口。
- 处理平台自身的审计日志、访问控制和操作留痕。

### 4.3 平台侧当前不需要负责的内容

平台侧不需要：

- 理解智能体内部 LangGraph、Skill 或 MCP 的调用细节。
- 分别对接每一个内部工具。
- 在前端复制审单、法规或报告生成逻辑。
- 自己解析模型私有思考过程。
- 首期提供正式文件中心才能完成联调。

## 6. 通用 Agent 与固定工作流的区别

### 6.1 通用 Agent

使用：

```json
{
  "options": {
    "intent": "auto"
  }
}
```

或者：

```json
{
  "options": {
    "intent": "chat"
  }
}
```

通用 Agent 会看到全部已注册工具，但系统提示词要求它只调用完成当前用户目标所需的能力，不得因为报关数据中出现 HS 编码、CIF、价格等字段就自动计算税费，也不得自动生成报告或扩展为完整流程。

重要限制：当前通用 Agent 主要读取 `message.content`。如果平台希望通用 Agent 分析某份报关数据，应把用户问题和必要业务正文一起放进 `message.content`。不要只把正文放在 `business_context.declaration_text` 而让 `message.content` 为空。

### 6.2 固定工作流

固定工作流必须由平台显式指定：

- `audit`：只执行审单工作流。
- `report`：只执行报告生成。
- `regulation_search`：只执行法规检索。
- `declaration_query`：只执行报关数据查询。
- `full_review`：执行完整演示审查链路。

`auto` 不会因为存在报关数据而自动升级为 `full_review`。

平台如果有明确、可重复的业务流程，应优先使用固定 intent；用户自由问答和工具组合任务使用 `auto` 或 `chat`。

```env

AGENT_V1_AUTH_ENABLED=false
AGENT_V1_USE_PLATFORM_FILES=false
```

说明：

- `AGENT_V1_ENABLED` 当前默认已经是 `true`。
- `AGENT_V1_DEMO_MODE=true` 时，完整审查使用演示数据和演示报告。

```json
  "business_context": {},
  "options": {
    "intent": "auto",
    "response_mode": "stream",
    "include_tool_trace": true,
    "include_structured_result": true,
    "output_file_policy": "agent_temporary",
    "timeout_seconds": 600
  }
```

## 13. SSE 流式协议

### 13.1 连接方式

```http
GET /api/agent/v1/runs/{run_id}/events
Accept: text/event-stream
```

响应头包括：

```text
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```

单条事件格式：

```text
id: 4
event: tool_started
data: {"schema_version":"1.0","run_id":"run-xxx","sequence":4,"event":"tool_started","data":{"tool":"audit_declaration","display_name":"audit_declaration"}}

```

### 13.2 事件清单

| event | 平台处理方式 |
| --- | --- |
| `agent_started` | 显示任务开始 |
| `status_changed` | 更新阶段文字和加载状态 |
| `message_delta` | 将 `data.content` 追加到当前回答 |
| `tool_started` | 展示工具名称和执行中状态 |
| `tool_progress` | 更新工具进度，当前部分能力可能不发送 |
| `tool_finished` | 将工具状态改为完成，可展示摘要 |
| `output_created` | 增加文件、图片或结构化产物 |
| `warning` | 显示非阻断警告 |
| `heartbeat` | 保持连接和显示任务仍在运行 |
| `agent_completed` | 结束流并读取最终答案、结果和 Outputs |
| `agent_failed` | 结束流并展示结构化错误 |
| `agent_cancelled` | 结束流并显示已取消 |

### 13.3 正常事件顺序示例

```text
agent_started
status_changed
message_delta
tool_started
tool_finished
message_delta
output_created（可选）
agent_completed
```

### 13.4 SSE 重连

每个事件都有递增的 `sequence`，同时通过 SSE `id` 返回。

连接断开后，平台可以携带：

```http
Last-Event-ID: 4
```

服务将从第 5 条事件继续发送，避免重复展示。

### 13.5 浏览器侧注意事项

原生 `EventSource` 只适合简单 GET，无法方便地附加自定义服务认证 Header。推荐：

1. 平台后端建立到智能体 SSE 的连接，再转发给平台前端；或者
2. 平台前端使用 `fetch` 读取响应流，但智能体接口仍由平台后端代理。

不要把 `X-Agent-Service-Key` 暴露给浏览器。

## 14. 查询最终状态

```http
GET /api/agent/v1/runs/{run_id}
```

成功结果重点字段：

```json
{
  "run_id": "run-xxx",
  "status": "completed",
  "final_answer": "审单完成，未发现明显风险。",
  "structured_result": {},
  "outputs": [],
  "warnings": [],
  "error": null,
  "last_sequence": 7,
  "context_version": 1,
  "usage": {
    "duration_ms": 1234
  }
}
```

状态枚举：

```text
queued
running
waiting_external
completed
partially_completed
failed

```

即使平台已经消费 SSE，也建议在终止事件后再请求一次状态接口，以状态快照作为最终落库依据。

## 15. 文件和图片 Output 处理

### 15.1 当前演示模式

首期统一使用：

```json
{
  "output_file_policy": "agent_temporary"
}
```

生成文件会出现在 `outputs`：

```json
{
  "output_id": "out-xxx",
  "kind": "document",
  "format": "docx",
  "name": "customs-review.docx",
  "mime_type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  "size": 12345,
  "sha256": "...",
  "agent_output_url": "/api/agent/v1/outputs/out-xxx/content",
  "metadata": {
    "storage": "agent_temporary"
  },
  "expires_at": "2026-06-21T10:00:00Z"
}
```

平台后端应将相对地址拼接为：

```text
http://127.0.0.1:8000/api/agent/v1/outputs/out-xxx/content
```

然后代理给浏览器下载。

### 15.2 文件元数据接口

```http
GET /api/agent/v1/outputs/{output_id}
```

### 15.3 文件下载接口

```http
GET /api/agent/v1/outputs/{output_id}/content
```

如果启用租户认证，下载时必须携带与 Run 相同的 `X-Tenant-ID`。

### 15.4 后续接入平台文件中心

平台需要提供一个 multipart 上传接口，至少接收：

```text
file: 文件二进制
name: 文件名
metadata: JSON 字符串
```

平台返回：

```json
{
  "file_id": "platform-file-xxx",
  "preview_url": "https://platform.example/files/xxx/preview",
  "download_url": "https://platform.example/files/xxx/download"
}
```

智能体侧配置：

```env
AGENT_V1_USE_PLATFORM_FILES=true
AGENT_V1_PLATFORM_FILE_UPLOAD_URL=https://platform.example/internal/files
AGENT_V1_PLATFORM_FILE_API_KEY=replace-with-service-key
```

上传成功后，Output 返回 `platform_file_id`、`preview_url` 和 `download_url`。

上传失败时，当前实现会自动退回智能体临时托管，并返回 `OUTPUT_UPLOAD_FAILED` warning，不会直接丢失生成文件。

### 15.5 当前文件限制

- 默认临时文件有效期为 86400 秒。
- 本地 Output 元数据注册表当前驻留在进程内存中。
- 服务重启后，磁盘文件可能仍然存在，但旧 `output_id` 不能保证继续下载。
- 正式环境应优先接入平台文件中心，或后续将 Output 元数据改为持久化存储。
- 图片 Output 协议已经预留，但当前图片生成和多模态链路不作为首期交付能力。

## 16. 附件输入协议

附件字段已预留：

```json
{
  "attachments": [
    {
      "file_id": "platform-file-001",
      "kind": "image",
      "name": "declaration.png",
      "purpose": "declaration_ocr",
      "mime_type": "image/png",
      "size": 102400,
      "download_url": "https://platform.example/temp/file-001",
      "expires_at": "2026-06-20T12:00:00Z",
      "sha256": "64位十六进制摘要"
    }
  ]
}
```

安全要求：

- 智能体只下载 `AGENT_V1_ATTACHMENT_ALLOWED_HOSTS` 白名单中的 URL。
- 只允许 HTTP/HTTPS。
- 默认单文件最大 20MB。
- 支持过期时间和 SHA-256 校验。
- 禁止重定向下载。
- 下载完成后任务临时目录会清理。

当前多模态暂缓，因此平台首期不要发送附件。

## 17. 鉴权与租户隔离

### 17.1 演示阶段

同服务器、受控环境可暂时使用：

```env
AGENT_V1_AUTH_ENABLED=false
```

平台仍应传：

```http
X-Request-ID: trace-xxx
X-Tenant-ID: tenant-demo
X-Service-Name: customs-platform
```

### 17.2 开启服务认证

智能体配置：

```env
AGENT_V1_AUTH_ENABLED=true
AGENT_V1_SERVICE_API_KEY=replace-with-strong-random-key
```

平台请求 Header：

```http
X-Agent-Service-Key: replace-with-strong-random-key
X-Tenant-ID: tenant-demo
X-Service-Name: customs-platform
X-Request-ID: trace-xxx
```

认证开启后：

- 缺少或错误的服务密钥返回 401。
- 缺少 `X-Tenant-ID` 返回 400。
- Header 租户与请求体租户不一致返回 403。
- Run 和 Output 查询均校验租户。
- 服务会在响应 Header 返回 `X-Request-ID`。

## 18. 幂等、会话和并发

### 18.1 request_id 幂等

`request_id` 在同一租户内必须唯一。

- 相同 `tenant_id + request_id + 请求内容` 重复提交：返回原 Run，不重复执行。
- 相同 `tenant_id + request_id` 但请求内容不同：返回 409 `IDEMPOTENCY_CONFLICT`。

平台重试创建请求时必须复用原 `request_id`，不要每次生成新值。

### 18.2 session_id

平台应为同一用户的同一业务会话复用 `session_id`，不同用户不得共用默认会话 ID。

建议格式：

```text
tenantId:userId:businessConversationId
```

### 18.3 同会话串行

当前服务会对相同 `tenant_id + session_id` 的任务加锁，避免同一会话并发修改上下文。

不同会话可以并行执行。

### 18.4 context_version

平台可以携带 `context_version` 做乐观并发控制。提交过旧版本会返回 409 `SESSION_CONTEXT_CONFLICT`。

首期平台也可以不传，由智能体自动生成下一版本。

## 19. 错误结构和重试策略

统一错误示例：

```json
{
  "error": {
    "error_code": "RUN_TIMEOUT",
    "message": "智能体任务执行超时",
    "retryable": true,
    "stage": "run_execution",
    "dependency": null,
    "details": {},
    "trace_id": "trace-xxx"
  }
}
```

平台处理规则：

- `retryable=true`：可提示用户重试，自动重试最多 1 至 2 次。
- `retryable=false`：不要自动重试，应修正参数或权限。
- HTTP 4xx：通常为调用方参数、认证或资源问题。
- HTTP 5xx：通常为智能体内部或依赖服务异常。
- SSE 中收到 `agent_failed` 后停止等待，并读取 `data.error`。
- `partially_completed` 表示主任务已完成，但存在 warning，例如平台文件上传失败后退回本地托管。

常见错误码：

| error_code | 含义 | 平台处理 |
| --- | --- | --- |
| `SERVICE_AUTH_FAILED` | 服务密钥错误 | 检查服务配置 |
| `TENANT_HEADER_REQUIRED` | 缺少租户 Header | 补充 Header |
| `TENANT_ACCESS_DENIED` | 跨租户访问 | 阻止并记录 |
| `IDEMPOTENCY_CONFLICT` | request_id 被不同请求复用 | 使用新 request_id 或恢复原请求 |
| `SESSION_CONTEXT_CONFLICT` | 会话版本过旧 | 刷新会话状态 |
| `RUN_NOT_FOUND` | Run 不存在 | 检查 run_id |
| `RUN_TIMEOUT` | 执行超时 | 按 retryable 重试 |
| `OUTPUT_NOT_FOUND` | Output 不存在 | 提示文件不可用 |
| `OUTPUT_EXPIRED` | 临时文件过期 | 重新生成 |
| `OUTPUT_UPLOAD_FAILED` | 平台文件上传失败 | 使用本地 fallback |

## 20. 平台侧推荐调用流程

平台后端建议封装一个 `CustomsAgentClient`，只向业务层暴露以下方法：

```text
createRun(request)
streamEvents(runId, lastEventId)
getRun(runId)
cancelRun(runId)
getOutput(outputId)
downloadOutput(outputId)
getCapabilities()
healthCheck()
```

完整处理流程：

```text
1. 平台校验用户权限。
2. 生成 request_id、session_id、user_id、tenant_id。
3. POST /runs。
4. 保存 run_id 与平台业务记录的关联。
5. 连接 events_url。
6. message_delta 追加到回答区域。
7. tool_started/tool_finished 更新工具状态。
8. output_created 增加文件或图片项。
9. agent_completed/failed/cancelled 结束 SSE。
10. GET status_url 获取最终快照。
11. 平台落库 final_answer、structured_result、outputs 和错误信息。
12. 用户点击文件时，由平台后端代理下载。
```

## 21. 平台侧 SSE 伪代码

```javascript
async function runCustomsAgent(payload) {
  const created = await platformApi.post('/internal/customs-agent/runs', payload);

  const response = await fetch(created.events_url, {
    headers: {
      Accept: 'text/event-stream'
    }
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder('utf-8');
  let buffer = '';

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const blocks = buffer.split('\n\n');
    buffer = blocks.pop() || '';

    for (const block of blocks) {
      const eventName = getSseField(block, 'event');
      const data = JSON.parse(getSseField(block, 'data'));

      if (eventName === 'message_delta') {
        appendAssistantText(data.data.content);
      } else if (eventName === 'tool_started') {
        showToolRunning(data.data.tool, data.data.display_name);
      } else if (eventName === 'tool_finished') {
        showToolFinished(data.data.tool, data.data.summary);
      } else if (eventName === 'output_created') {
        addOutput(data.data.output);
      } else if (
        ['agent_completed', 'agent_failed', 'agent_cancelled'].includes(eventName)
      ) {
        return await platformApi.get(created.status_url);
      }
    }
  }
}
```

具体实现可以使用平台现有 HTTP/SSE 库，不要求照搬此代码。

## 22. Completion Callback

请求可以附加：

```json
{
  "callback": {
    "completed_url": "https://platform.example/internal/agent-completed"
  }
}
```

当前安全要求：

- 必须是 HTTPS。
- 域名必须配置在 `AGENT_V1_CALLBACK_ALLOWED_HOSTS`。
- 智能体会 POST 完整 RunSnapshot。
- 如果设置了服务密钥，回调携带 `X-Agent-Service-Key`。
- 回调失败不会改变主任务结果，只会增加 `CALLBACK_DELIVERY_FAILED` warning。

首期平台已经消费 SSE 时，可以暂不使用 callback。

## 23. Run 持久化与服务重启

当前使用 SQLite 保存：

- RunSnapshot
- 有序事件列表
- request_id 幂等索引

服务重启后：

- 已完成 Run 可以继续查询。
- 重启前仍在执行的 Run 会被标记为 `failed`。
- 错误码为 `RUN_INTERRUPTED_BY_RESTART`，允许平台使用新 request_id 重试。

当前是单实例演示设计，不支持多个智能体进程同时共享同一 SQLite 文件。

## 24. 平台文件中心接口约定

正式接入前，平台侧需要确认：

1. 上传 URL。
2. 服务端认证方式。
3. 最大文件大小。
4. 返回字段中的 `file_id`、`preview_url`、`download_url`。
5. 文件有效期和权限继承方式。

## 25. 联调步骤

### 阶段一：服务可达

1. 启动智能体服务。
2. 平台后端请求 `/health`。
3. 确认 `status=ok`。
4. 请求 `/capabilities` 并记录能力状态。

### 阶段二：普通 Agent

1. 使用 `intent=auto` 创建简单文本任务。
2. 获取 `run_id`。
3. 消费 SSE。
4. 验证 `message_delta`。
5. 验证至少一个工具调用场景的 `tool_started/tool_finished`。
6. 验证 `agent_completed`。
7. 查询最终 RunSnapshot。

### 阶段三：固定审单

1. 使用 `intent=audit`。
2. 在 `business_context.declaration_text` 提供文本。
3. 验证审单步骤事件和最终结构化结果。

### 阶段四：文件输出

1. 使用 `intent=full_review` 和 `agent_temporary`。
2. 验证 `output_created`。
3. 查询 Output 元数据。
4. 下载 DOCX。
5. 校验文件大小和 SHA-256。

### 阶段五：异常场景

1. 重复提交同 request_id。
2. 使用错误租户访问 Run。
3. 主动取消 Run。
4. SSE 断线后使用 Last-Event-ID 重连。
5. 下载过期或不存在的 Output。

## 26. 首期验收标准

满足以下条件即可认为平台首期接入完成：

- 平台可以成功创建 Run。
- 平台可以稳定消费 SSE。
- 文本增量不会重复或丢失。
- 工具开始和结束状态能正确展示。
- 任务终止后平台能取得最终快照。
- 显式 `audit` 不会自动扩展为税费计算或报告生成。
- 显式 `full_review` 可以完成演示链路。
- DOCX Output 可以通过平台页面下载。
- 相同 request_id 重试不会重复创建任务。
- 服务重启后历史已完成 Run 仍可查询。

## 27. 当前已知限制

当前版本定位为单服务器演示和平台首次联调版本，尚有以下限制：

- 多模态和图片识别不作为当前主链路承诺。
- `batch_audit`、图片转 Excel、模板填报仍需继续完善。
- 通用 Agent 尚未自动注入全部 `conversation_context` 和 `business_context`，关键内容应放进 `message.content`。
- 本地 Output 元数据未持久化，服务重启后旧临时文件链接不保证有效。
- SQLite RunStore 适合单实例，不适合多副本部署。
- 演示环境默认关闭服务认证，正式环境必须开启或由平台网关严格隔离。
- Completion Callback 当前只允许 HTTPS 和白名单域名。
- 真实报关系统尚未接入，报关查询和流程演示可使用 mock 数据。

这些限制不影响当前“平台创建任务、消费 SSE、查看工具状态、获取最终结果、下载演示文件”的完整联调链路。
