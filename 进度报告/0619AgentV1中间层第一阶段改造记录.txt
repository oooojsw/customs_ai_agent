【2026-06-19】Agent V1 中间层第一阶段改造记录
================================================

一、本轮目标
-----------

在不改变现有 /api/v1/*、web/ 前端和核心 Agent 行为的前提下，建立平台集成中间层第一版：

- 统一协议模型。
- 进程内 RunStore。
- 标准 Event/SSE。
- Chat/Audit 旧能力适配器。
- 独立 /api/agent/v1/* 路由。
- 默认关闭的特性开关。
- 契约和并发测试。

四、新增接口
-----------

- POST /api/agent/v1/runs
- GET /api/agent/v1/runs/{run_id}
- GET /api/agent/v1/runs/{run_id}/events
- POST /api/agent/v1/runs/{run_id}/cancel
- GET /api/agent/v1/outputs/{output_id}
- GET /api/agent/v1/outputs/{output_id}/content
- GET /api/agent/v1/capabilities
- GET /api/agent/v1/health

当前 intent 支持：

- auto/chat：通过 ChatAdapter 调用现有 CustomsChatAgent。
- audit：通过 AuditAdapter 调用现有 RiskAnalysisOrchestrator。
- ocr：下载平台附件，通过 VisionBackend 调用现有或后续视觉模型。

附件下载和临时 Output 已接入。默认 Host 白名单为空，因此未配置时外部附件会被拒绝。
现有 /api/v1/analyze_image 仍保持不变。

当前 LegacyTableOcrBackend 只返回文本。后续专用视觉模型若返回含 TableResult 的
DocumentResult，OcrAdapter 会自动生成 XLSX，并根据 output_file_policy 上传平台文件中心
或使用智能体临时托管。


五、协议行为
-----------

- request_id 在 tenant 范围内幂等。
- 相同 request_id + 相同请求返回原 run_id。
- 相同 request_id + 不同内容返回 IDEMPOTENCY_CONFLICT。
- sequence 从 1 单调递增。
- 支持 Last-Event-ID 从指定 sequence 后读取。
- thinking 事件不对外暴露模型私有推理内容。
- 完成、失败和取消由 RunStore 原子写入终止事件和终止状态。
- 并发完成/取消时只能产生一个终止事件。
- heartbeat 默认 20 秒。
- 普通 Run 必须以 agent_completed、agent_failed 或 agent_cancelled 结束。

七、当前限制
-----------

- RunStore 为进程内存储，服务重启后 Run/Event 丢失。
- 不支持多进程共享；生产阶段需替换 Redis/数据库实现。
- 平台鉴权尚未接入。
- 平台文件中心只定义了发布接口，尚未配置真实平台客户端。
- Report、Batch 尚未接入 Agent V1 Adapter。
- OCR Adapter 已接入，但当前上游 Legacy OCR 只返回文本，尚不能真实恢复表格结构。
- XLSX 渲染器已完成，等待专用视觉模型提供 TableResult。
- 未修改现有 chat_agent.py 的内部工具架构。
- Agent V1 默认关闭。
