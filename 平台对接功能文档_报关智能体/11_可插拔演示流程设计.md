# 11 可插拔演示流程设计

## 背景

当前三个 Mock 报关演示：

```text
normal_release
returned_then_release
high_risk_inspection
```

本质是 `data/mock_customs_cases/*.json` 里的案例数据，不是三套独立工作流。它们共用同一套状态机和工具。

这对稳定报关流程是好事，但不适合让多模态负责人自由增加演示流程。例如“图片表格识别 -> 生成 Excel -> 审单 -> 报告”不应该写进海关状态机。

## 建议设计

保留两层：

```text
硬流程：Mock 报关状态机
软流程：可插拔 demo_flow
```

硬流程用于稳定展示真实报关阶段。

软流程用于演示多模态、Skill、组合工具、报告等能力。

## 建议目录

```text
data/demo_flows/
  table_ocr_to_audit/
    manifest.json
    prompt.md
    inputs/
    expected_outputs/

  table_ocr_to_declaration/
    manifest.json
    prompt.md
    inputs/
    expected_outputs/

  image_to_report/
    manifest.json
    prompt.md
    inputs/
    expected_outputs/
```

## manifest.json 示例

```json
{
  "flow_id": "table_ocr_to_audit",
  "title": "图片表格识别到智能审单",
  "description": "识别报关单图片，输出 DocumentResult JSON，再执行智能审单。",
  "entry_intent": "auto",
  "allowed_skills": ["table_ocr", "image_recognition"],
  "allowed_tools": [
    "audit_declaration",
    "generate_compliance_report"
  ],
  "input_kinds": ["image"],
  "output_kinds": ["structured_data", "spreadsheet", "document"],
  "prompt_file": "prompt.md",
  "mock": true
}
```

## prompt.md 示例

```md
你要演示一次图片表格识别到智能审单的流程。

步骤：
1. 使用 table_ocr 识别用户上传的报关单图片。
2. 输出 DocumentResult JSON，必须包含 fields、tables、confidence、warnings。
3. 从 fields 和 tables 中提取报关字段。
4. 调用审单能力检查风险。
5. 如果存在低置信度字段，必须提示人工复核。
6. 最终输出审单摘要，并生成可下载的结构化结果。

不要宣称识别百分百准确。低置信度字段必须标注 needs_review=true。
```

## 平台如何调用

第一阶段可以不新增接口，仍然走：

```http
POST /api/agent/v1/runs
```

在 `business_context` 里传：

```json
{
  "demo_flow_id": "table_ocr_to_audit"
}
```

后端读取 `data/demo_flows/table_ocr_to_audit/manifest.json` 和 `prompt.md`，拼入智能体上下文，让智能体按流程调用工具。

## 为什么不把所有流程都做成状态机

状态机适合：

```text
报关申报、海关受理、审单、退单、查验、征税、放行、结关
```

因为这些阶段必须稳定、可复现、可画流程条。

文字流程适合：

```text
图片识别
表格转 Excel
识别后审单
报告生成
图片生成填写后报关单
多模态演示
```

因为这些能力变化快，适合通过 Skill 和 Prompt 扩展。

## 给多模态负责人的任务

他可以维护：

```text
data/skills/table_ocr/
data/skills/image_recognition/
data/demo_flows/table_ocr_to_audit/
data/demo_flows/table_image_to_xlsx/
data/demo_flows/image_to_declaration_preview/
```

每个 demo_flow 至少包含：

```text
manifest.json
prompt.md
一到三个样例输入
expected_outputs/ 标准 JSON 或截图说明
```

## 验收标准

新增一个演示流程时，不需要改 Agent V1 接口，不需要改平台前端主流程。

平台仍然只消费：

```text
message_delta
tool_started
tool_finished
output_created
agent_completed
agent_failed
agent_cancelled
```
