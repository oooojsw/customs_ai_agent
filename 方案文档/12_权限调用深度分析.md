## 25. 权限调用流程（核心问题）

### 25.1 问题本质

当海关智能体通过 HTTP API 向 OpenCode 发送消息后，OpenCode 内部的 LLM 会使用工具。当它使用工具时，会触发 OpenCode 的权限系统。

**关键代码**（`permission/next.ts` 第 116-146 行）：

```typescript
export const ask = fn(..., async (input) => {
  const rule = evaluate(permission, pattern, ruleset, approved)

  if (rule.action === "deny")
    throw new DeniedError(...)  // 直接拒绝

  if (rule.action === "ask") {  // ⚠️ 阻塞等待！
    return new Promise<void>((resolve, reject) => {
      s.pending[id] = { info, resolve, reject }
      Bus.publish(Event.Asked, info)  // 发布事件
    })
    // 这个 Promise 只有在收到 PermissionNext.reply() 后才会 resolve
  }

  if (rule.action === "allow") continue  // 直接放行
})
```

### 25.2 阻塞问题

当权限配置为 `"ask"` 时：

1. OpenCode LLM 调用工具（如 bash）
2. `ask()` 发布 `permission.asked` 事件
3. **返回一个永不 resolve 的 Promise**
4. OpenCode 的消息处理流程被**永久阻塞**
5. 海关智能体的 HTTP 调用也**永久挂起**

**这意味着：如果配置了 `"ask"` 权限，且没有程序化监听器，OpenCode 会死锁。**

### 25.3 解决方案

#### 方案 A：全部配置为 "allow" 或 "deny"（推荐）

不使用 `"ask"`，避免阻塞：

```json
{
  "permission": {
    "read": "allow",
    "glob": "allow",
    "grep": "allow",
    "list": "allow",
    "bash": "deny",
    "edit": "deny",
    "write": "deny",
    "task": "allow"
  }
}
```

**优点**：简单可靠，不会死锁
**缺点**：bash/edit/write 被完全禁止

#### 方案 B：使用 "ask" + 自动回复监听器

在 SSE 事件流中监听 `permission.asked` 事件，自动回复：

```python
import asyncio
import json


class PermissionAutoHandler:
    """权限自动处理器"""

    def __init__(self, client, allowed_tools=None, denied_tools=None):
        self.client = client
        self.allowed_tools = allowed_tools or {"read", "glob", "grep", "list", "task"}
        self.denied_tools = denied_tools or {"bash", "edit", "write"}
        self._task = None

    async def start(self):
        """启动权限监听"""
        self._task = asyncio.create_task(self._listen_permissions())

    async def stop(self):
        """停止权限监听"""
        if self._task:
            self._task.cancel()
            try:
                await self._task
            except asyncio.CancelledError:
                pass

    async def _listen_permissions(self):
        """监听 SSE 事件流中的权限请求"""
        try:
            async with self.client._client.stream("GET", "/event") as response:
                async for line in response.aiter_lines():
                    if not line.startswith("data: "):
                        continue

                    try:
                        data = json.loads(line[6:])
                        event_type = data.get("type", "")
                        properties = data.get("properties", {})

                        if event_type == "permission.asked":
                            await self._handle_permission_request(properties)

                    except (json.JSONDecodeError, Exception):
                        continue

        except asyncio.CancelledError:
            raise
        except Exception as e:
            print(f"[PermissionHandler] 监听异常: {e}")

    async def _handle_permission_request(self, request: dict):
        """处理单个权限请求"""
        request_id = request.get("id")
        permission = request.get("permission", "")

        if not request_id:
            return

        # 根据权限类型决定回复
        if permission in self.allowed_tools:
            reply = "once"
            print(f"[PermissionHandler] 自动允许: {permission}")
        elif permission in self.denied_tools:
            reply = "reject"
            print(f"[PermissionHandler] 自动拒绝: {permission}")
        else:
            reply = "reject"  # 默认拒绝
            print(f"[PermissionHandler] 默认拒绝: {permission}")

        try:
            await self.client._client.post(
                f"/permission/{request_id}/reply",
                json={"reply": reply}
            )
        except Exception as e:
            print(f"[PermissionHandler] 回复失败: {e}")
```

**在 main.py 中使用**：

```python
# 启动 OpenCode 服务器后
if opencode_client:
    from src.services.opencode.permission_handler import PermissionAutoHandler

    permission_handler = PermissionAutoHandler(
        client=opencode_client,
        allowed_tools={"read", "glob", "grep", "list", "task"},
        denied_tools={"bash", "edit", "write"}
    )
    await permission_handler.start()
    app.state.permission_handler = permission_handler
```

#### 方案 C：在 Session 创建时传入权限（最优）

如果 Session.create 支持 `permission` 字段，可以在创建会话时覆盖全局配置：

```python
# 创建只读会话
session = await client.create_session(
    workspace_dir="data",
    title="只读会话"
)
# 然后通过 PATCH /session/:id 更新权限
# 或在创建时通过 permission 字段设置
```

**但注意**：Session.create 的 schema 中 `permission` 字段类型是 `PermissionNext.Ruleset`（数组格式），不是简单的字符串配置。

## 28. 另一个关键问题：OpenCode 内部 LLM 的工具调用

OpenCode 的 LLM 在处理消息时可能会自动使用工具（bash、read、write 等）。海关智能体只发送了文本消息，但 OpenCode 的 LLM 可能会决定执行 bash 命令或其他操作。

**这意味着**：

1. 即使海关智能体没有显式调用 bash 工具，OpenCode 的 LLM 也可能自己决定执行
2. 权限配置需要覆盖 OpenCode 内部 LLM 的所有工具调用
3. 推荐将 bash/edit/write 设为 "deny" 以防止意外操作

### 完全禁用 OpenCode 内部工具的方案

如果只想使用 OpenCode 的 HTTP API（文件搜索、读取），不想让 OpenCode 内部 LLM 自主操作，可以通过配置禁用工具：

```json
{
  "permission": {
    "bash": "deny",
    "edit": "deny",
    "write": "deny",
    "task": "deny",
    "question": "deny"
  }
}
```

这样 OpenCode 的 LLM 就无法执行任何修改操作，只能读取和搜索。
