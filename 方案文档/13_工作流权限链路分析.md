## 29. 权限检查架构

### 29.1 每个工具的权限检查点

**所有工具在执行前都会调用 `ctx.ask()` 进行权限检查**：

```typescript
// tool/read.ts 第 34 行
await ctx.ask({
  permission: "read",
  patterns: [filepath],
  always: ["*"],
  metadata: {},
});

// tool/bash.ts 第 149 行
await ctx.ask({
  permission: "bash",
  patterns: Array.from(patterns),
  always: Array.from(always),
  metadata: {},
});

// tool/write.ts 第 34 行
await ctx.ask({
  permission: "edit",
  patterns: [path.relative(Instance.worktree, filepath)],
  always: ["*"],
  metadata: { filepath, diff },
});
```

### 29.2 ctx.ask() 的内部实现

```typescript
// prompt.ts 第 681-688 行
async ask(req) {
  await PermissionNext.ask({
    ...req,
    sessionID: input.session.id,
    tool: { messageID: input.processor.message.id, callID: options.toolCallId },
    ruleset: PermissionNext.merge(input.agent.permission, input.session.permission ?? []),
  })
}
```

**规则合并顺序**：Agent 权限 → Session 权限 → 全局配置

### 29.3 external_directory 额外检查

当工具访问**项目目录之外**的文件时，会额外检查 `external_directory` 权限：

```typescript
// external-directory.ts 第 12-31 行
export async function assertExternalDirectory(ctx, target, options) {
  if (Instance.containsPath(target)) return; // 在项目目录内，跳过
  // 在项目目录外，检查 external_directory 权限
  await ctx.ask({
    permission: "external_directory",
    patterns: [glob],
    always: [glob],
  });
}
```

## 30. 两种操作模式的权限差异

### 30.1 模式 A：直接 HTTP API（无权限检查）

| API                          | 功能     | 权限检查 | 说明                        |
| ---------------------------- | -------- | -------- | --------------------------- |
| `GET /file?path=...`         | 列出目录 | ❌ 无    | 直接调用 `File.list()`      |
| `GET /file/content?path=...` | 读取文件 | ❌ 无    | 直接调用 `File.read()`      |
| `GET /file/status`           | 文件状态 | ❌ 无    | 直接调用 `File.status()`    |
| `GET /find?pattern=...`      | 搜索文本 | ❌ 无    | 直接调用 `Ripgrep.search()` |
| `GET /find/file?query=...`   | 搜索文件 | ❌ 无    | 直接调用 `File.search()`    |

**结论**：这些端点完全绕过 OpenCode 内部的工具系统和权限系统。海关智能体可以安全使用，不受任何权限限制。

### 30.2 模式 B：会话消息（完整权限检查）

| API                         | 功能       | 权限检查    | 说明                          |
| --------------------------- | ---------- | ----------- | ----------------------------- |
| `POST /session/:id/message` | 发送消息   | ✅ 完整检查 | OpenCode LLM 可能使用任何工具 |
| `POST /session/:id/command` | 发送命令   | ✅ 完整检查 | OpenCode LLM 处理命令         |
| `POST /session/:id/shell`   | 执行 Shell | ✅ 完整检查 | OpenCode LLM 调用 bash        |

**结论**：这些端点触发 OpenCode 内部 LLM，LLM 可能使用任何工具。每个工具调用都经过权限检查。

## 31. 海关智能体每个工具的权限需求分析

### 31.1 opencode_create_session

```
海关工具 → POST /session {title, ...}
```

- **内部操作**：创建 Session 对象，不涉及文件/命令操作
- **权限需求**：无
- **风险**：✅ 无

### 31.2 opencode_read_file

```
海关工具 → GET /file/content?path=xxx
```

- **内部操作**：直接调用 `File.read()`，不经过 LLM
- **权限需求**：无（HTTP API 绕过）
- **风险**：✅ 无

### 31.3 opencode_search_files

```
海关工具 → GET /find/file?query=xxx
```

- **内部操作**：直接调用 `File.search()`，不经过 LLM
- **权限需求**：无（HTTP API 绕过）
- **风险**：✅ 无

### 31.4 opencode_search_text

```
海关工具 → GET /find?pattern=xxx
```

- **内部操作**：直接调用 `Ripgrep.search()`，不经过 LLM
- **权限需求**：无（HTTP API 绕过）
- **风险**：✅ 无

### 31.5 opencode_list_files

```
海关工具 → GET /file?path=xxx
```

- **内部操作**：直接调用 `File.list()`，不经过 LLM
- **权限需求**：无（HTTP API 绕过）
- **风险**：✅ 无

### 31.6 opencode_send_message ⚠️ 关键

```
海关工具 → POST /session/:id/message {parts: [{type: "text", text: "xxx"}]}
```

- **内部操作**：
  1. OpenCode 接收消息
  2. **OpenCode 内部 LLM 处理消息**
  3. **LLM 可能决定使用 bash/read/write/edit 等工具**
  4. 每个工具调用经过权限检查
- **权限需求**：取决于 LLM 决定使用什么工具
- **风险**：
  - 如果 LLM 使用 `bash` → 需要 `bash` 权限
  - 如果 LLM 使用 `read` → 需要 `read` 权限
  - 如果 LLM 使用 `write/edit` → 需要 `edit` 权限
  - 如果权限为 `"ask"` → **永久阻塞** 🔴

### 31.7 opencode_run_command ⚠️ 关键

```
海关工具 → POST /session/:id/shell {agent: "general", command: "ls -la"}
```

- **内部操作**：
  1. OpenCode 创建 shell 消息
  2. **OpenCode 内部 LLM 解释命令**
  3. **LLM 可能调用 bash 工具执行命令**
  4. bash 工具检查 `bash` 权限
- **权限需求**：`bash` 权限
- **风险**：
  - 如果 `bash` 为 `"deny"` → 命令无法执行 🔴
  - 如果 `bash` 为 `"ask"` → 永久阻塞 🔴
  - 如果 `bash` 为 `"allow"` → 可以执行但有安全风险

## 33. 推荐方案：混合模式

### 方案 A：只用直接 HTTP API（最安全）

**完全不使用 `opencode_send_message` 和 `opencode_run_command`**

```python
# 只注册这些安全工具：
safe_tools = [
    "opencode_create_session",  # 创建会话
    "opencode_read_file",       # 读取文件
    "opencode_search_files",    # 搜索文件名
    "opencode_search_text",     # 搜索文本
    "opencode_list_files",      # 列出目录
    # 不注册 opencode_send_message
    # 不注册 opencode_run_command
]
```

**权限配置**：不需要（所有操作都绕过权限系统）

**优点**：100% 安全，不会遇到任何权限问题
**缺点**：不能执行命令、不能让 OpenCode LLM 处理复杂任务

### 方案 B：使用会话 + 严格权限

```json
{
  "permission": {
    "read": "allow",
    "glob": "allow",
    "grep": "allow",
    "list": "allow",
    "task": "allow",
    "bash": "deny",
    "edit": "deny",
    "write": "deny",
    "question": "deny",
    "external_directory": "deny"
  }
}
```

**效果**：

- `opencode_send_message` → LLM 可以读取文件，但不能执行命令或写入
- `opencode_run_command` → 命令会被拒绝（bash: deny）⚠️

**问题**：`opencode_run_command` 无法工作，因为 bash 被 deny 了

### 方案 C：使用会话 + bash allow（需要信任）

```json
{
  "permission": {
    "read": "allow",
    "glob": "allow",
    "grep": "allow",
    "list": "allow",
    "bash": "allow",
    "edit": "deny",
    "write": "deny",
    "question": "deny",
    "external_directory": "allow"
  }
}
```

**效果**：

- `opencode_send_message` → LLM 可以读取和执行命令，但不能写入
- `opencode_run_command` → 命令可以执行

**风险**：bash 被完全放行，OpenCode LLM 可以执行任何命令

### 方案 D：推荐方案 — 直接 API + 选择性会话

```python
# 1. 大多数操作使用直接 HTTP API（无权限问题）
# 2. 只在需要复杂处理时使用会话消息
# 3. 使用 prompt_async 避免阻塞

# opencode_send_message 改为使用 prompt_async：
async def opencode_send_message_safe(input_str: str) -> str:
    """发送消息到 OpenCode（使用 prompt_async 避免权限阻塞）"""
    parts = input_str.split("|", 1)
    session_id = parts[0].strip()
    message = parts[1].strip()

    # 使用 prompt_async（fire-and-forget）
    await self.client._client.post(
        f"/session/{session_id}/prompt_async",
        json={"parts": [{"type": "text", "text": message}]}
    )

    # 等待一段时间后获取结果
    await asyncio.sleep(5)
    messages = await self.client.get_messages(session_id, limit=2)

    # 提取最新助手回复
    for msg in reversed(messages):
        if msg.get("info", {}).get("role") == "assistant":
            parts_list = msg.get("parts", [])
            text = ""
            for p in parts_list:
                if p.get("type") == "text":
                    text += p.get("text", "")
            return text

    return "消息已发送，请稍后查看结果"
```

- `doom_loop: ask` — 检测重复工具调用时询问（可通过 `PermissionAutoHandler` 自动拒绝）
