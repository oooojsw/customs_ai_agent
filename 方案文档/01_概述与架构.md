## 1. 概述

### 1.1 项目目标

将 OpenCode 开发环境本地化集成到海关智能体系统中，使智能体能够在不依赖用户全局安装 OpenCode 的情况下，自动调用 OpenCode 的文件处理、代码执行、程序编辑等能力。

**核心方式：直接使用 OpenCode 源码项目，通过 `bun run dev serve` 启动 headless HTTP 服务器。不需要安装任何额外的 npm 包。**

### 1.2 核心需求

| 需求类型     | 具体描述                              | 优先级 |
| ------------ | ------------------------------------- | ------ |
| 本地化部署   | 无需用户全局安装 OpenCode，直接用源码 | P0     |
| 自动启动管理 | FastAPI 启动时自动启动 OpenCode 服务  | P0     |
| 工具封装     | 封装成核心工具供智能体调用            | P0     |
| 安全隔离     | 限制 OpenCode 的访问范围和操作权限    | P0     |
| 错误处理     | 完善的异常捕获和恢复机制              | P1     |
| 性能优化     | 异步架构，连接池复用                  | P1     |

### 1.3 技术选型

| 组件               | 选型                       | 说明                                     |
| ------------------ | -------------------------- | ---------------------------------------- |
| OpenCode 运行时    | OpenCode 源码 + Bun 运行时 | 直接用源码目录，`bun run dev serve` 启动 |
| Python HTTP 客户端 | httpx                      | 异步 HTTP 客户端，已在项目依赖中         |
| 服务管理           | asyncio subprocess         | 原生异步进程管理                         |
| 工具注册           | LangChain StructuredTool   | 复用现有 MCP Bridge 架构                 |
| 配置管理           | JSON 配置文件              | 与现有 MCP 配置一致                      |

## 2. 项目分析

### 2.1 OpenCode 项目

**项目路径**: `C:\Users\ZhuanZ\Desktop\opencode re\opencode - copy`

**技术栈**: TypeScript + Bun 运行时 + Hono Web 框架

**启动方式**:

- `bun run dev` - 启动 TUI（交互式终端界面）
- `bun run dev serve` - 启动 headless HTTP 服务器（**推荐用于集成**）
- 完整命令：`bun run dev serve --port 4096 --hostname 127.0.0.1`
- 底层等价于：`bun run --cwd packages/opencode --conditions=browser src/index.ts serve --port 4096 --hostname 127.0.0.1`

**重要说明**：

- **不需要安装 `oh-my-opencode-windows-x64` 包**，直接使用源码运行
- 海关项目的 `package.json` 中虽然有 `oh-my-opencode-windows-x64` 依赖，但 node_modules 里并未安装
- 正确做法是：Python 启动时通过 `subprocess.Popen` 在 OpenCode 源码目录下执行 `bun run dev serve`

**关键特性**:

- 标准 REST API + SSE 事件流
- 会话管理（Session）
- 文件操作（File Read/Write/Edit/Search）
- 工具执行（Bash/Grep/Read/Write/Edit）
- MCP 服务器管理
- 权限控制系统
